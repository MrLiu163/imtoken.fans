# M1-A2 推荐方案：内容优先的社区首页

**结论**：采用“紧凑入口 + 帖子主流 + 轻侧栏”的社区结构。首屏先给 4 张板块入口，紧接着就是帖子流，不再做介绍站式长页。视觉沿用 Logo 的白底、深蓝和玫红，不跟参考站用黑色主题。

## 1. 删除旧版冗余（必需）
- 删除大 Hero、带编号的四块导航、四板块说明区、旧 AI 数据流和结尾口号。
- 删除 1200px 容器上限。全站只保留一组四板块入口，顶栏导航除外。
- 首页不展示旧 AI 历史数据。AI 共创只作为“产品反馈”下的子分类出现。

## 2. 布局与尺寸
| 断点 | 外边距 | 栅格 |
|---|---|---|
| ≥1440 | 32px | `minmax(0,1fr) 320px`，间距 24px |
| 1024–1439 | 24px | `minmax(0,1fr) 300px`，间距 20px |
| 768 | 20px | 单栏，侧栏移到主流之后，两列卡片 |
| 375/390 | 16px | 单栏；四入口排成 2×2 |

- 页面底色为浅灰，内容放在白色卡片里。宽屏下主流不封顶。
- 正文行宽用 `max-width: 72ch`，只限制详情正文这一列，不限制容器。
- 1920 宽度下，帖子列表允许摘要左侧加 240px 封面，避免长行。
- 整页禁止横向溢出。标签栏可以单独横向滑动。

## 3. 视觉 Token
- **颜色**：
  - 玫红 `--brand-rose: #E8336D`，用于主按钮、选中状态和点赞激活
  - 深蓝 `--brand-navy: #14213D`，用于标题和顶栏文字
  - 页面底 `--bg: #F5F6F8`，卡片 `#FFF`，边框 `#E6E8EE`
  - 次要文字 `#5B6475`，弱文字 `#8A93A3`
  - 状态色：待处理（灰）、讨论中 `#2563EB`、已记录 `#0F9D58`。这些只是演示状态，不代表官方处理。
- **字体**：
  - 字体栈：`system-ui, "PingFang SC", "Noto Sans SC", sans-serif`
  - 字号：H1 22/30；帖子标题 17/26（移动端 16）；正文 15/26；元信息 13/20；Badge 12
  - 英文模式允许标题换两行，按钮宽度不写死
- **间距与圆角**：间距用 4 的倍数，卡片内边距 20px（移动端 16px），列表项之间用分隔线，不再给每条单独加卡片阴影。圆角：卡片 12px，标签 999px。
- **焦点**：`outline: 2px solid #E8336D; offset 2px`。点击区域不小于 44px。

## 4. 页面线框

### 首页 `/`
```
顶栏 64px（移动端 56）：Logo | 首页 钱包安全 产品反馈 综合交流 活动 | 中/EN | 登录 | [发帖]
演示条 36px：演示社区 · 内容与互动为示例，不写入真实账号
欢迎行：一句话“在 imToken Fans 交流钱包安全、反馈产品、参与活动”（不超过 1 行，无插画）
四入口（桌面 4 列 / 手机 2×2，高约 112px）：图标 + 名称 + 3 个方向（小字，用 · 分隔）
┌ 主流 ───────────────────────┐ ┌ 侧栏 320 ┐
│ Tab：推荐 最新 热门            │ │ 成长示例卡 │
│ Chip：全部 安全 反馈 交流 活动 │ │ 热门话题  │
│ 帖子 ×12，第 8 条后“加载更多”  │ │ 社区公告  │
└──────────────────────────────┘ └──────────┘
```
- 四入口每张整卡都是 `<a href="/community/{section}">`。3 个内容方向只是文字，不做独立链接。
- 内容方向：
  - 钱包安全：防骗识别 · 备份与授权 · 使用求助
  - 产品反馈：imToken 问题建议 · AI 共创 · 更新日志
  - 综合交流：提问讨论 · 研究报告 · 行业观察
  - 活动：活动公告 · 社区活动 · 签到抽奖
- 侧栏最多 3 块，不放四板块入口。移动端侧栏只保留成长卡，排在第 4 条帖子之后；话题和公告放到列表末尾。

### 板块页 `/community/[section]`
- 板块名只允许 safety、feedback、discussion、activities 四个，其他值走 404。
- 结构：面包屑 → 板块头（名称、一句介绍、示例帖数、[发帖]）→ 子分类 Chip → 置顶/精选 1–2 条（左侧玫红竖条加“精选”标签）→ 帖子列表 → 侧栏（成长卡 + 本板块热门）。
- 产品反馈额外提供状态筛选（全部/待处理/讨论中/已记录），和子分类一起作用（AND）。

### 详情页 `/community/[section]/[postId]`
```
面包屑：首页 / 产品反馈 / AI 共创
主栏：[演示帖] 标签 + 标题 → 作者行（头像、昵称、LevelBadge、时间、类别/状态）
      → 正文（72ch）→ 图片位 16:9 → 互动栏（点赞、投票、收藏示例）
      → 评论区（热门/最新、评论输入、评论 + 1 级回复）→ 相关帖子 3 条
侧栏：作者卡（头像、等级、示例发帖数）→ 成长示例卡 → 本板块热门 5 条
```
- 移动端：侧栏下移到相关帖子前面。底部固定一条互动栏（点赞、评论、投票），要留出安全区。

## 5. 组件规范
- **PostListItem**：头像 36、昵称、LevelBadge、板块/类别 Chip、反馈状态（可选）、标题最多 2 行、摘要最多 2 行（移动端 3 行）、可选封面（桌面放右侧 160×100，移动端放在摘要下方 16:9）、元信息行（时间 · 评论 · 赞 · 投票）。整行可点；行内的 Chip 不单独可点，避免链接嵌套。
- **LevelBadge**：直接复用现有组件，不新建。作者都是原创虚拟作者，不给官方认证标识。
- **GrowthDemoCard**：
  - 标题“成长示例”，内容示例：Lv2 · 总 XP 760，进度条 760/1600，“距 Lv3 还差 840”
  - 说明文案：“交流、共创、参与活动积累成长”
  - 链接：我的资料 `/profile`、成长说明 `/faq#xp`、`/activities`
  - 登录后仍显示示例数据，并加一行“非你的账户数据”
  - 不写任何 XP 奖励数值
- **数据（必需）**：至少 12 条帖子，每板块至少 2 条详情；feedback 覆盖 wallet、ai、changelog 三类。不写真实版本号、真实奖励或官方回复。

## 6. 状态
| 状态 | 表现 |
|---|---|
| 加载 | 列表骨架 6 条（头像圆 + 3 行条），侧栏骨架 |
| 空 | “该分类暂无示例帖子” + [查看全部] |
| 失败 | “示例内容加载失败” + [重试]（静态数据一般不会失败，组件仍要预留） |
| 404 | 板块名或帖子 ID 无效时，显示“帖子不存在” + 返回板块 |
| 未登录 | 发帖/评论按钮可点，打开演示预览，同时提示“登录不会改变演示数据” |

## 7. 演示边界（必需）
- 点赞、投票、评论、回复只存在当前页面状态里。互动区下方说明一次：“演示互动，刷新后恢复”。
- **发帖预览**：用 Dialog（移动端为全屏 Sheet）。字段：板块（下拉）、标题（≤60 字）、正文（≤2000 字）。提交后只在弹窗内渲染预览卡，并标注“仅预览，未发布”。
- 不上传、不写库、不调用 ServerAction，不把演示 postId 传给任何真实接口。
- 实现如果需要超出上述边界，交主调度上报。

## 8. 无障碍与语言
- Tab 用 `role=tablist`，Chip 用 `aria-pressed`。键盘可走到所有按钮，Dialog 打开时锁定焦点，Esc 可关闭。
- 封面图写 alt。点赞等计数变化用 `aria-live="polite"` 播报。
- 中英文案用 key 映射，英文模式下按钮不截断。

## 9. 交付说明
- **待决策**：顶栏是否加搜索框（建议 M2 再做）；公告的具体文案由主调度提供。
- **可调整**：封面比例、侧栏宽度（300–340px）、Chip 样式。
- **风险/未验证**：本方案没有看过现有组件代码。LevelBadge 和等级阈值按 Brief 写的是 Lv3 = 1600，实现前需要和现有配置核对。375–1920 各断点的效果需要开发截图验收。
