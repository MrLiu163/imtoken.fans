## 团队如何预览

在自己的任务分支完成开发和检查后推送至 GitHub，再创建以 `main` 为目标的 PR。查看 PR 的 Vercel 部署状态或机器人提供的预览链接；构建成功才代表该版本可访问。后续向同一分支推送会产生新的预览版本。

PR 审查与主分支保护仍然有效；预览成功不会自动合并代码。合入 `main` 后 Vercel 更新主站。主站的本次部署只是演示发布，不能当作真实业务已经验收。

公开仓库中的外部 PR 代码可能读取部署环境变量；不要把高权限生产密钥提供给不受信任的预览。当前未给这个项目配置数据库等凭证，未来启用真实业务时另行确认环境变量范围与鉴权回调。
