# imToken Fans 多 agent 工作流与使用说明

更新：2026-10-14。已配置角色，不代表工程功能已开发。当前 M1 仍未开始。
模型可调度清单、公开价格与客户端差异见 [模型说明](agent-models.md)。

## 1. 最快使用方法

在这个项目的主聊天里说清目标即可，由主调度按需读取配置、拆任务和调用角色。主对话承担总调度，不默认再生成一个调度子 agent。

启动工程：

> 按项目 agent 工作流开始 M1。先用文案和设计 agent 完成首页与四板块导航方案，整合后由前端实现并验收。采用默认性价比配置，最多三个子 agent 并发，这一批先完成首页和导航。

只设计，暂不开发：

> 调用 designer 和 copywriter，给钱包安全板块做中英内容与页面方案，暂不修改应用代码。

定向开发：

> 按工作流开发产品反馈状态，先让 backend 给出模型和权限方案，主调度统一接口后再实现、由 reviewer 独立审查。

更节省：

> 这批按更省模式做：探索、文案和明确的小修复交 Luna，核心逻辑用 Sol，暂停非必要角色和 Astra，仍完成必需验收。

指定旧模型比较：

> 本次文案任务用 gpt-5.6-luna / medium，与默认配置比较返工和用量；只覆盖本次，不改全局设置。

指定复核：

> 用 reviewer 检查这批改动，只报告有证据的问题；必要时再调用 architect 定向分析，暂不修代码。

查看进度：

> 汇报各 agent、文件归属、已完成项、验证结果和阻塞，继续当前批次。

暂停/调整：

> 停止本批子 agent，保留现有文件并汇报进度；等我重新指定范围。

用户指令决定当前任务边界。配置咨询或安装不自动开始工程；普通新任务也不默认召集全体角色。

## 2. 配置与角色

| 位置/角色 | 默认模型 | 强度 | 职责与输出 |
| --- | --- | --- | --- |
| 主对话 / `.codex/config.toml` | GPT-6.1 Sol | medium | 范围、决策、任务卡、分派、整合、验收、路线图 |
| explorer | GPT-6 Luna | medium | 只读代码/依赖盘点，给事实和路径 |
| copywriter | GPT-6 Luna | medium | 中英对照、术语、键建议；有归属才写 messages |
| designer | GPT-6.1 Sol | medium | 页面结构、品牌规范、组件/交互状态；全站设计按需 high |
| frontend | GPT-6.1 Sol | medium | 页面/组件/交互，复杂逻辑按需 high |
| fixer | GPT-6 Luna | high | 规范明确的局部调整和小修复 |
| backend | GPT-6.1 Sol | high | 模型、迁移、权限、服务端、媒体 |
| qa | GPT-6 Luna | medium | 相关工程/功能验证、复现证据；复杂浏览器工作按需 Sol |
| reviewer | GPT-6.1 Sol | high | 独立只读检查重要改动 |
| architect | GPT-6 Astra | low | 升级的具体难题，不常驻 |

角色 TOML 是 Prompt 与默认模型的单一来源；主配置显式注册角色，并设置子 agent 默认 Luna/medium、最多 3 个子 agent 并发。实际运行还受会话工具上限约束。无需每次启动所有角色。

总调度的角色指令在项目配置和根 AGENTS.md 中。`.codex/agents/` 文件可纳入版本管理，供下一次工作复用；用户个人 `~/.codex/config.toml` 和权限设置不在本次修改范围。

## 3. 如何确保角色与模型真正应用

依据 [官方 Subagents 文档](https://learn.chatgpt.com/docs/agent-configuration/subagents) 与 [配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)，本地 Codex 支持项目自定义角色及模型/推理配置。

但当前已开始的聊天不会因为新写 TOML 就证明角色已热加载。模型选择器、显式启动参数和客户端行为可能影响主模型。项目默认是新会话建议，不声称改变本轮已经在运行的主模型。

主调度按以下顺序执行：

1. 读选定 `.codex/agents/<role>.toml`，取得 Prompt、模型和推理强度。
2. 若当前接口支持命名角色，使用角色；固定模型/强度来自该文件，不能假定仅在聊天中说升级就覆盖成功。
3. 若接口只有通用 spawn（本聊天的接口如此），读取角色文件，将其 developer_instructions 与任务卡作为任务指令传入，**显式传 model 和 reasoning_effort**。不同模型使用独立上下文启动（当前接口为 `fork_turns="none"`），明确工作目录、用户约束、必读资料与可写文件。不要只用角色名称或依赖默认继承。
4. 本次模型覆盖使用通用 spawn 并传入角色指令，避免命名角色的固定值覆盖本次要求；不擅自修改长期角色文件。
5. 记录请求配置与工具实际回执，不采信模型自述型号。缺实际推理路由证据时，只能确认请求被接口接受和任务执行，不能断言服务端内部路由。
6. 模型不可用时先记录错误，选择当前接口支持的回退并说明，不静默改用更贵模型。轻任务回退可选 5.6 Luna；核心回退可选 6 Sol/5.6 Terra/5.6 Sol，选择前检查当前可用性与成本。Astra 仅作难题升级。

推荐新聊天直接在同一项目打开，以重新读取配置；当前聊天也可按上述显式分派方式使用。CLI 模型目录与桌面/本会话存在差异，见模型说明；CLI 未验证路径不能标为可用。

## 4. 标准流程

### A. 定义任务与依赖

主调度读取用户最新要求、路线图、当前代码；创建 [任务卡](tasks/template.md)，用具体路径分配文件归属、输入/输出和验收。首先解决跨模块模型/接口约定，再并行实现。

### B. 按需探索、文案与设计

独立只读任务适合并行。文案输出双语键与文本，设计输出组件与状态；由主调度消除矛盾。设计不直接改代码，文案未经文件归属不编辑 JSON。

### C. 实现与整合

按路径独立的前后端任务可并行；同文件写入串行。明确的小变更交 fixer，跨组件和核心业务交 Sol。主调度负责接口整合，不能靠“最后覆盖”处理冲突。

### D. 验证与独立复核

qa 执行本批相关验收；关键权限、数据库、钱包/登录、上传、跨组件状态变化安排 reviewer。必需工程检查集中在整合后运行，不让多个 agent 对同一环境同时 build、迁移或活动写入。简单低影响修改仅做必要检查，不强制加独立审查。

### E. 完成交付

收集简洁结论、文件、验证、风险；修复确认问题后只复测受影响范围。主调度更新任务卡与 roadmap，报告当前结果和限制，不自动跳到下一里程碑。

## 5. 文件与环境归属

- `messages/zh.json` 与 `messages/en.json` 由同一写入者维护，默认 copywriter；若仅提供建议则主调度或指定实现者一次性落地。
- `src/app/globals.css` 与共享 UI 一次一人负责；designer 给规范，指定 frontend/fixer 落地。
- `src/lib/types.ts`、公共接口、数据库迁移由主调度与 backend 定约，具体写入只给一个人；历史迁移不重写。
- `package.json`、锁文件、配置由主调度或一个指定开发者负责；不由各模块自行安装依赖。
- `roadmap.md`、任务卡和总体决策由主调度维护；子 agent 只交报告。
- 默认共享同一工作目录，禁止覆盖别人改动。以后需要多个写入分支时先建立可用的 Git 基线，再按任务需要使用 worktree；当前仓库无提交，不自动提交全部文件。
- 所有角色继承主会话权限。Prompt 中“只读”和文件归属是行为约束，不是独立安全沙箱。
- 写库、账号/活动测试只在明确的开发环境进行；部署、外部操作按用户授权范围处理，不因并行而扩大授权。

## 6. 升级与控制成本

轻任务先 Luna；需要协调多个组件或业务约束用 Sol；同一路径经一次针对性重试仍失败，带具体证据升级，不反复重复整段尝试。任务越界、接口争议或缺环境立即交主调度。

Astra 由主调度按需启动，收到具体问题和已有证据后返回建议；代码执行与验证仍由相应角色负责。不能因为任务叫“安全”就常驻最高模型，也不能因便宜把权限或迁移设计交给无上下文的轻模型。

有必要时使用同一任务比较模型，记录工具实际提供的用量、耗时、返工和验收；不足以推导账单就标未知。更省模式减少角色、上下文和重复检查，保留必需验收。

## 7. 配置安装验证

静态检查：Python 3.11+ 解析 TOML，核对注册、角色、模型和文档；`npm run check-i18n` 验证现有双语基础。
运行检查：Codex 渲染配置和当前聊天显式模型分派；它们不等于新聊天自动发现全部角色或 CLI 模型调用已全部验证。
应用检查：本次不修改 src/messages/Supabase/public/包依赖；不执行 M1。安装验证结果已写入 [模型说明](agent-models.md)，包含严格配置读取、两次显式模型分派及未验证项。
