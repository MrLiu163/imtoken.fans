# M1-A2 社区首页与板块演示 review

状态：**可预览版本已完成，等待用户review**。日期：2026-10-15。

## 用户反馈与本批决策

原版重复介绍多、版心窄，不像可直接使用的社区。本批参考 [小米社区](https://www.xiaomi.cn/) 的内容主栏、社区侧栏与作者等级信息层级，保留imToken Fans品牌；[只读观察](../design/M1-A2-reference-notes.md)、[Claude设计交付](../design/M1-A2-design-v1.md)。

取消大Hero与结束口号，用一组紧凑四板块入口解释内容方向，进入板块、列表、详情，主栏直接展示原创演示帖，侧栏结合现有成长与活动入口。桌面流体宽度。

## 数据与功能边界

本轮用户明确要求虚拟内容供预览。演示内容独立于原Supabase，虚拟作者、计数和成长均标示；点赞、投票、评论、回复和发帖预览仅本页状态，不发布、不写库、不发XP。既有AI与活动入口是原功能，未因本批演示宣称完成业务改造。

## 分工

总调度整理参考、Brief、文件归属与浏览器验收；Claude一次设计修订；GPT developer统一页面、交互、双语实现。本批不触及权限/数据库/媒体上传，不默认额外运行安全QA。

## Review 重点

- 一进入是否知道可以去哪个板块、看什么、如何参与。
- 内容密度与宽度是否合适，首屏是否更像社区。
- 板块子分类、反馈状态、帖子与评论的组织是否符合预期。
- 成长与活动是否帮助理解参与路径，且不会误认为示例数值是自己的账户。

## 检查记录

工程检查：`npm run check-i18n`通过（1039键），`npm run lint`通过，`npm run build`通过，新增两个动态路由；未新增依赖或迁移。

最终生产预览：`npm run start`仍固定127.0.0.1:3000，中英首页、反馈板块与详情实际加载通过，已保存无开发工具浮层的桌面/手机截图。之后恢复`npm run dev`供用户继续预览和修改。

恢复开发服务后，最后一次浏览器等待networkidle超时（60秒）；导航已提交且document complete，随后按所需DOM确认四入口与首页标题正常。记录为网络空闲等待限制，不把它记为页面未加载，也未据此宣称性能通过。

HTTP只读检查：中英首页、四板块及12详情共34个URL均200并含对应语言演示标识；无效板块、无效帖子、跨板块错误ID均显示not-found并带robots noindex。Next当前带loading边界的流式not-found响应实测HTTP200，不能把UI 404描述成HTTP404；行为与安装版Next `not-found.md`一致。[原始结果](../reviews/M1-A2-http-checks.json)

浏览器已验证：

- 1440宽时主容器1376、左右32；1920宽时主容器1856、左右32。首页只有一组四板块说明入口。
- 390中文、375英文与768英文无整页横向溢出，手机四入口2×2；短列表/过滤结果也仅显示一张成长示例。成长计算Lv2/760XP/16%/距升级840XP。
- 推荐/最新/热门排序、键盘方向键切换、加载8→12帖、AI分类与已记录状态AND筛选的空态及重置通过。
- 点赞24→25，投票31→32；添加评论与一级回复，评论3→5；刷新后恢复3条与原点赞/投票状态。
- 发帖弹窗填写并显示“仅预览，未发布”；Esc关闭焦点回到触发按钮。手机弹窗修正UA默认限制后，390宽时实测全宽390、left0。
- 手机底部评论按钮会聚焦并滚动到输入框；菜单展开、Esc关闭及焦点恢复通过。

上述为演示流程与渲染验收；真实账号发布、社区写入、媒体上传、XP授予和原签到/抽奖/OAuth业务未作本批验收。演示组件未导入真实Actions、Supabase或fetch；既有Auth/访问埋点沿用原行为，不能把演示隔离误写成整个站点没有网络或埋点请求。
